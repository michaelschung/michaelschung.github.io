InstagramHelperService

libs/instagram-helper/src/lib/instagram-helper.service.ts — ~4,070 lines, ~50 methods

Summary

InstagramHelperService is the central engine for all of Pinpoint's Instagram DM automation. It receives raw webhook events from Instagram (comments, DMs, postbacks, story mentions), matches them against creator-configured campaigns, and orchestrates the sending of automated drip sequences, giveaways, blasts, and contact-info collection flows. It also handles audience segmentation, credit metering, AI-powered comment/DM moderation, and Instagram compliance webhooks (deauthorize/delete).

This is a shared NestJS library (@pinpoint-monorepo/instagram-helper) consumed by the backend API and worker apps. It's the largest single service in the monorepo, acting as the business logic layer between Instagram's Graph API and Pinpoint's database.

Key Concepts

Drip (IgDrip)A single step in a campaign — can be text, image, post share, button, combo, carousel, contact form, or giveaway.
Blast (InstagramBlast)A one-time bulk DM sent to a fan audience (like an email blast, but via IG DMs).

Webhook Entry Point

handleWebhook(payload) L783–819

The single entry point for all Instagram webhook events. It iterates over payload.entry and dispatches based on the shape of each entry:

  • 'changes' in entry → Comment → handleComment()
  • 'messaging' in entry with 'postback' → Button press → handlePostback()
  • 'messaging' in entry otherwise → DM / Story mention → handleMessage()
Side Effect: Webhook Passthrough

In production, events from PASSTHROUGH_IDS (Pinpoint's own test accounts) are forwarded to dev.pinpointapp.xyz and Hookdeck for debugging. L808–818

Comment Handling

handleComment(entry, event) L3020–3199

Processes incoming Instagram comments on a creator's posts or reels. The flow:

  1. Look up TeamInstagramAccount by the IG media owner ID
  2. Upsert the fan's InstagramUser record
  3. Check for keyword-matched drip campaigns via checkKeywordCampaigns() — if the comment text matches a campaign keyword, trigger it
  4. If no keyword match, check "any comment" campaigns via checkAnyCommentCampaigns() — campaigns configured to trigger on any comment on a specific post
  5. If a campaign is triggered: check filters, deduct credits, record the IgTriggerComment, auto-reply to the comment if configured, and trigger the drip campaign
  6. If no campaign matched, run comment moderation (AI)
flowchart TD A[handleComment] --> B[Look up TeamIgAccount & upsert fan] B --> C{Keyword campaign match?} C -->|Yes| D[Check filters & credits] C -->|No| E{Any-comment campaign?} E -->|Yes| D E -->|No| F[handleCommentModeration] D -->|Pass| G[Record IgTriggerComment] D -->|Fail| H[Skip] G --> I[Auto-reply to comment if configured] I --> J[triggerCampaign]
checkKeywordCampaigns() L1341–1423

Finds all active drip campaigns for the team IG account that are keyword-triggered (DripCampaignTrigger.KEYWORD) or ad-triggered with keywords. Normalizes the incoming text (strips emojis, lowercases) and checks if any campaign keyword appears in the message. Returns the first match.

Special handling: strips emojis using emoji-regex, trims whitespace. If the campaign has exactMatch enabled, requires exact equality rather than substring.

checkAnyCommentCampaigns() L1424–1511

Finds campaigns configured with DripCampaignTrigger.ANY_COMMENT and checks if the comment's media ID matches one of the campaign's target media IDs (or the campaign's associated MetaAdCollection media IDs). Returns the first match.

DM Handling

handleMessage(entry, event) L3541–3584
handleDM(entry, event, teamIgAccount, igUser) L3440–3539

handleMessage is the dispatcher — it deduplicates by message ID, skips deleted messages, upserts the fan, then routes to handleDM() for text messages or handleStoryMention() for story mentions.

handleDM is the core DM processing logic:

  1. Update the fan's blastWindowEnds to now + 24 hours (Instagram messaging window) and mark conversation as unread
  2. If the team has DM-based data collection enabled, check if the message contains contact info (phone/email)
  3. Try to match the message to a keyword campaign
  4. If no campaign matched, mark the conversation as organic and run DM moderation
  5. If campaign matched, check filters, deduct credits, record IgTriggerDm, and trigger the campaign
Side Effect: Blast Window Reset

Every incoming DM extends the fan's blast eligibility window to 24 hours from now. This is critical for blast functionality — fans must have DM'd within 24h to receive blasts. L3461–3462

Postback / Button Handling

handlePostback(entry, event) L3848–3955

Processes button taps and icebreaker selections. Parses the postback payload JSON and dispatches:

  • BUTTON → handleButtonPress() — finds the IgButton record, sends button response text, handles alert notifications. Special case: if the button's drip has sequence === -1, it's an "Accept DM" button that triggers the associated campaign. L3693–3795
  • OPT-IN → processes contact info opt-in, sends the contact form follow-up, publishes to InstagramSubscribe SQS queue L3902–3935
  • ICEBREAKER → handleIcebreaker() — triggers the associated campaign L3797–3846
Gotcha: Legacy Icebreaker Format

Icebreaker payloads can come in two formats: the legacy "ICEBREAKER|{campaignId}" pipe-delimited format is converted to JSON before processing. L3883–3886

Campaign Triggering

checkFilters() L1512–1658

Evaluates whether a fan passes a campaign's eligibility filters before triggering. Checks include:

  • Follower-only filter — if enabled, fan must follow the business
  • One-time trigger — checks if the fan has already triggered this campaign (via IgTriggerDm or IgTriggerComment). If limitPerFan is set, enforces that limit.
  • Frequency cap — limits how often a fan can trigger across all campaigns within a time window
  • Brand new fan check — if the campaign's onlyBrandNew flag is set, checks the IG Conversations API to verify this is the fan's first-ever interaction
triggerCampaign() L1659–1725

The heart of campaign execution. For each active drip in the campaign (ordered by sequence):

  1. Skip drips with sequence < 0 (these are special: -1 = "Accept DM" button, -2 = thank-you message)
  2. Schedule a Graphile Worker task (processIgDrip) with a delay based on the drip's delaySeconds
  3. If the campaign is a postback trigger, mark the first drip as charge-exempt (the "Accept DM" step is free)

Note: the actual message sending happens asynchronously via the worker — triggerCampaign() only schedules the tasks.

Drip Processing

processIgDrip(payload) L2679–2757

Called by the Graphile Worker task ProcessIgDripTask. This is where individual drip messages are actually sent:

  1. Load the drip and its associated campaign, team IG account
  2. Check that the campaign is still active and the drip hasn't been cancelled
  3. Create an IgOutboundDm record
  4. If it's a contact drip, route to processContactDrip()
  5. If it's a giveaway drip, route to handleGiveawayDm()
  6. Otherwise, format the message via formatIgMessage() and send via sendIgMessage()
flowchart TD A["Graphile Worker: processIgDrip"] --> B[Load drip & campaign] B --> C{Campaign still active?} C -->|No| D[Skip] C -->|Yes| E[Create IgOutboundDm] E --> F{Drip type?} F -->|Contact| G[processContactDrip] F -->|Giveaway| H[handleGiveawayDm] F -->|Other| I[formatIgMessage] I --> J[sendIgMessage] G --> K[Send contact form / opt-in] H --> L[Pick winner & send result]

Message Formatting & Sending

formatIgMessage() L1878–2002

Converts a drip's DB representation into the Instagram Graph API message payload. Handles all drip types:

TypeIG API Format
TEXT (IgTextDm)Simple text message
MEDIA (IgMediaDm)Image/video attachment URL
POST (IgPostDm)Media share (Instagram post ID)
BUTTON (IgButtonDm)Generic template with buttons (postback payloads)
COMBO (IgComboDm)Generic template with image + text + buttons
CAROUSEL (IgCarouselDm)Horizontal scrolling cards, each with image + title + buttons
CONTACT (IgContactDm)Routed to separate flow — not formatted here
GIVEAWAY (IgGiveawayDm)Routed to separate flow — not formatted here

For all templates with buttons, each IgButton is serialized as a postback with payload {"type":"BUTTON","buttonId":"..."}.

sendIgMessage() L2436–2531

Makes the actual POST to https://graph.instagram.com/v24.0/{igId}/messages with the formatted payload. On success, updates the IgOutboundDm status to SENT. On failure, marks as FAILED with the error message. Retrieves the access token from AWS Secrets Manager for each send.

sendIgCommentReply() L2532–2596

Replies to an Instagram comment via POST https://graph.instagram.com/v24.0/{commentId}/replies. Creates an IgOutboundComment record and updates its status on success/failure.

hideIgComment() L2597–2639

Hides a comment by setting hide=true via the Graph API. Used by the moderation system to auto-hide flagged comments.

Giveaways

handleGiveawayDm() L1802–1877

Handles giveaway drips in campaigns. If the fan is the randomly selected winner, sends the win message; otherwise sends the lose message. The winner is selected by checking if one has already been picked for this drip — if not, the current fan becomes the winner.

handleGiveawayBlast() L1726–1801

Similar logic but for blast-based giveaways. Selects a random winner from all blast recipients and sends win/lose messages accordingly.

Audience Segmentation

Methods for building Prisma queries that filter fans based on saved audience segments.

buildSegmentWhereConditions() L124–270

Converts an IgUserSegment (or snapshot) into Prisma WHERE conditions. Supports filtering by:

  • Follower status — isFollower
  • Data collection mode — has phone, email, both, or neither
  • Automations triggered — fan must have triggered specific campaigns (via trigger DMs or comments)
  • Giveaways won — fan won specific giveaways (drip or blast)

Respects the segment's filterLogicalOperator (AND vs OR) for combining conditions.

getFanIdsPlain() / getFanIdsAmount() / getFanIdsAmountCombo() L272–692

Query methods for retrieving fan IDs matching segment filters. Support cursor-based pagination and chunked processing (5,000 per chunk) for large audiences. getFanIdsAmountCombo unions fans across multiple segments with deduplication.

Credits System

Credit flow

Teams on BASE or GROWTH plans have a finite credit balance (InstagramFreeCredit). Each active drip step in a campaign costs 1 credit.

  • igOnCredits() L712–722 — checks if a team is on a credit-based plan
  • checkAndDeductCredits() L863–897 — counts active drips in a campaign, verifies sufficient credits, deducts them. Returns false if insufficient.
  • deductCredits() L821–861 — performs the actual deduction and sends notifications:
    • At 20 credits remaining: sends a warning email
    • At 0 credits: sends depletion email + Slack notification

Fan Management

updateInstagramUserInfo() L1077–1158

The central fan upsert method — called on every webhook event. Creates or updates the InstagramUser record:

  1. Fetch fresh profile info from Instagram's Graph API via requestFanInformation()
  2. If the fan has a profile picture, download it and upload to S3 (with the IG account ID as the key prefix)
  3. Upsert the InstagramUser record with the latest name, username, follower count, profile pic URL, follow status
Note: API errors are swallowed

requestFanInformation() returns null on any API error rather than throwing. The upsert still proceeds but with stale/missing profile data.

isBrandNewFan() L899–935

Checks the Instagram Conversations API to determine if a fan has ever DM'd the business before. Used by the "only brand new fans" campaign filter. Only runs if formLastSentAt is null (fast path: if they've been sent a form, they're not brand new).

AI Moderation

handleCommentModeration() L2758–3019

AI-powered comment moderation for teams that have it enabled (IgModeration). The flow:

  1. Check if the team has moderation configured and active
  2. Call aiService to classify the comment (spam, offensive, etc.)
  3. Based on moderation settings, may auto-hide the comment, auto-reply, or send creator notifications
  4. Records the moderation decision in the database

Supports configurable actions per classification: hide, reply, notify (email/SMS), or ignore.

handleDmModeration() L3200–3439

Similar to comment moderation but for organic DMs (not triggered by campaigns). Can auto-reply to DMs based on AI classification. Includes a cooldown mechanism (dmModerationCooldownEnds) to avoid spamming fans with moderation responses.

Story Mentions

handleStoryMention() + respondToStoryMention() L950–1076

When a fan mentions the creator in their Instagram story:

  1. Record the InstagramStoryMention in the database
  2. Download the story image from IG and re-upload to S3 (IG story URLs expire)
  3. Check if the creator has an active InstagramMentionAutoResponse configured
  4. If so, validate the fan passes filters (min follower count, not excluded, hasn't been responded to before)
  5. Send the auto-response DM

Compliance Webhooks

handleDeauthorizeWebhook() / handleDeleteWebhook() L3957–4070

Handle Instagram data compliance callbacks:

  • Deauthorize — when a user revokes the app's permissions. Decodes the signed request, deletes the access token from AWS Secrets Manager, and nulls out the secret key reference.
  • Delete — when a user requests data deletion. Same cleanup flow.

Both use decodeSignedRequest() L3957–3992 to base64-decode the Meta signed request payload.

Note: Signature verification is commented out

The HMAC signature verification in decodeSignedRequest() is currently commented out L3984–3989. The payload is decoded but not cryptographically verified against the app secret.

Gotchas & Notes

File size

At ~4,070 lines, this is the largest service in the monorepo. It handles a wide surface area — webhook processing, campaign logic, message formatting, API calls, moderation, compliance — all in one file. A future refactor could split it into focused sub-services (e.g., campaign, moderation, messaging, compliance).

Hardcoded passthrough IDs

The PASSTHROUGH_IDS array L113–119 contains hardcoded Instagram account IDs for webhook forwarding. Adding/removing test accounts requires a code change.

Commented-out sheet-based segmentation

The getFanIdsPlain() and getFanIdsAmount() methods contain commented-out code for loading fan IDs from uploaded spreadsheets in S3 L333–352. The idsFromSheet array is always empty, but all the chunking/pagination logic to handle it is still active.

Instagram API version

All Graph API calls use v24.0. This version is hardcoded in URL strings throughout the service rather than being configurable.

Credit deduction is non-atomic

checkAndDeductCredits() reads the credit balance, counts required drips, then updates — but this isn't wrapped in a transaction. Under high concurrency, two campaigns could both pass the credit check and over-deduct.
